# Как выкатить и откатить wb-template-generator

> Операторская карточка: минимум, который нужен в момент выката или аварии.
> Почему всё устроено именно так — в стандарте выката (ссылка в шапке репозитория).
> Плейсхолдеры ⟨…⟩ заполнить при переводе сервиса.

## 🚀 Выкатить

1. Смержить PR в `main` (squash) — выкат едет **сам**: сторож свежести → линт и тесты → сборка образов по git-SHA → выкат → проверка живости.
2. Следить: **Jenkins → wb-template-generator → deploy**. Зелёный прогон = версия в проде; выкаченный SHA виден в имени прогона.

Выкатить **конкретную версию** (не HEAD): та же джоба → **Build with Parameters** → `IMAGE_TAG` = метка (`main-<sha>`) или голый 40-символьный SHA. Образ не пересобирается — берётся готовый из реестра. *В прод принимаются только коммиты, уже влитые в `main`.*

Тестовой среды у сервиса нет — окружение одно, `prod`. Появится — добавляется строкой в `environments` в `Jenkinsfile`.

## ↩️ Откатить

1. **Jenkins → wb-template-generator → rollback → Build with Parameters.**
2. `TARGET_SHA` **пустой** = откат на предыдущую выкаченную версию (обычный случай); можно указать метку или голый SHA.
3. Если между версиями были миграции БД — старый код может не работать с новой схемой: убедиться, что миграция совместима с предыдущей версией кода (правило N−1).

Откат не требует согласования: сначала возвращаем рабочую версию, разбираемся после.

## 🔥 Если упало

| Симптом | Куда смотреть |
|---|---|
| Красная стадия **Deploy** | лог стадии; прод, скорее всего, остался на старой версии |
| Красная стадия **Verify** | сработал авто-возврат на предыдущую версию; в логе видно, что именно не ответило |
| «Что сейчас в проде?» | имя последнего зелёного прогона джобы deploy, либо `https://tgen.wirenboard.com/api/status` (поле `revision` = git-SHA) |
| Сервис молчит, выкатов не было | это не про выкат — смотреть логи контейнеров на хосте |

## 🧯 Jenkins недоступен (break-glass)

0. **Озвучить в общий канал и получить добро руководителя** (в остром инциденте — озвучить постфактум).
1. `ssh deploy@tgen.wirenboard.com`, каталог `/var/wb-services/wb-template-generator`.
2. Выкатить нужную версию руками (compose-файл на сервере остался от прошлого выката):
   ```bash
   export DEPLOY_TAG=⟨sha⟩
   docker compose -f docker-compose.deploy.yml pull
   docker compose -f docker-compose.deploy.yml up -d --wait
   ```
3. После инцидента — следующий выкат обычным путём через Jenkins.
