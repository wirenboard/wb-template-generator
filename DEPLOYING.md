# Как выкатить и откатить wb-template-generator

> Операторская карточка: минимум, который нужен в момент выката или аварии.
> Почему всё устроено именно так — в стандарте выката (ссылка в шапке репозитория).

У сервиса одна multibranch-джоба в Jenkins: **wb-template-generator**, внутри — по джобе на
ветку. Что делает прогон, решает ветка: любая ветка и PR — только проверки (`ci-lint`,
`ci-test`, дисциплина `CHANGELOG`), `main` — ещё и выкат в прод. У джобы ветки два параметра
на **Build with Parameters**: `ENVIRONMENT` и `REVISION`. Других нет.

## 🚀 Выкатить

1. Смержить PR в `main` (squash) — выкат едет **сам**: проверки → сборка образов по git-SHA → передача релиза джобе выката → проверка ревизии.
2. Следить за прогоном джобы `main`. Зелёный = версия в проде; в описании прогона — `prod @ <sha> · <кто смержил>`.

За выкат отвечает тот, кто смержил PR: его логин попадает в описание прогона и в алерты.

Прямой push в `main` **не выкатывается**: прогон встаёт в `NOT_BUILT` и шлёт алерт. В прод
попадает только смерженный PR.

## ↩️ Откатить (или перевыкатить)

1. Найти SHA нужной версии: джоба `main` → история прогонов → описание прогона вида
   `prod @ <sha> · <кто>`. Годится полный или короткий SHA. Что в проде сейчас —
   `https://tgen.wirenboard.com/api/status`, поле `revision`.
2. Джоба `main` → **Build with Parameters**.
3. `REVISION` = этот SHA, `ENVIRONMENT` оставить пустым → **Build**.
4. Дождаться зелёного прогона и проверить `revision` в `/api/status`.

Проверки при этом не перезапускаются, образы берутся готовые из `ghcr.io`. Если образа той
версии в реестре уже нет, он пересобирается из той же ревизии (не из HEAD) — и тогда
проверки прогоняются.

Если между версиями были миграции БД — старый код может не работать с новой схемой:
убедиться, что миграция совместима с предыдущей версией кода (правило N−1).

Откат не требует согласования: сначала возвращаем рабочую версию, разбираемся после.

## 🔥 Если упало

Упавший выкат — это красный прогон и алерт в Telegram-канал алертов Jenkins (первый зелёный
после него тоже объявляется). **Автоматического отката нет**: прод остаётся в том состоянии,
до которого дошёл выкат. Решить, что делать, и при необходимости откатить руками — раздел выше.

| Симптом | Куда смотреть |
|---|---|
| Красная стадия проверок или **Build** | лог стадии; прод не тронут, до выката дело не дошло |
| Красная стадия **Deploy**, код `deployment_failed` | лог прогона джобы `pipelines/deploy-infra`, который она запустила: роль не подняла стек или контейнер не стал healthy |
| Красная стадия **Deploy**, код `verification_failed` | образы уехали, но сервис не отдал новую ревизию: смотреть контейнеры на хосте и `https://tgen.wirenboard.com/api/status`. Проверка ревизии — последний шаг той же стадии, отдельной стадии у неё нет |
| `stale_branch` | ветка отстала от `main`: «Update branch» в GitHub и выкатить заново |
| `NOT_BUILT` с алертом | был прямой push в `main` — не выкачено; провести изменение через PR |
| `NOT_BUILT` без алерта | подряд два мержа: этот прогон уступил следующему, выкатит тот |
| «Что сейчас в проде?» | `https://tgen.wirenboard.com/api/status`, поле `revision` = git-SHA |
| Сервис молчит, выкатов не было | это не про выкат — смотреть логи контейнеров на хосте |

Подробности любого прогона — в артефакте `deployment-outcome.json`: фаза, код ошибки и образы, которые успели опубликоваться.

## 🧯 Jenkins недоступен (break-glass)

Только если Jenkins лежит **и** дело срочное. Согласование не нужно.

Выкатывать можно только образы, которые уже собрал конвейер и которые лежат в `ghcr.io`: собирать на сервере нельзя и сейчас.

1. Озвучить в общем канале, что выкатываете руками.
2. Зайти на хост, каталог `/var/wb-services/wb-template-generator`.
3. Найти ссылки на образы вида `ghcr.io/wirenboard/wb-template-generator-backend@sha256:…`. Что запущено сейчас — `docker inspect --format '{{.Config.Image}}' <контейнер>`; ссылки прошлых выкатов — в `deployment-outcome.json` на странице их прогона, если Jenkins хоть как-то открывается.
4. Вписать эти ссылки в `image:` файла `docker-compose.yml` в каталоге сервиса и поднять стек:

   ```bash
   docker compose up -d --wait
   ```

   Файл принадлежит роли `wb_template_generator` из `wirenboard/infra`: следующий выкат через Jenkins перезапишет его.

5. Проверить `https://tgen.wirenboard.com/api/status` — поле `revision`.
6. Когда Jenkins поднимется — выкатить ту же версию кнопкой `REVISION` (или влить исправление PR-ом), чтобы история прогонов снова совпадала с тем, что запущено. Написать разбор.
