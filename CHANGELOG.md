## [0.7.0] - 2026-07-16

### Добавлено
- **Тест** `test_llm_content.py` — контракт сборки LLM-контента (`assemble_llm_content`).

### Изменено
- **Модель по умолчанию `gpt-4o` → `gpt-5.6-luna`**: gpt-4o теряет регистры на image-based PDF, все gpt-5.x дают 100%; luna выбрана по балансу цена/качество (~$0.02/анализ).
- **`LLM_TEMPERATURE` по умолчанию → пусто**: gpt-5.x принимают только `temperature=1`. Для gpt-4o/локальных LLM детерминизм возвращается установкой `LLM_TEMPERATURE=0`.
- **Рефакторинг**: сборка vision-контента вынесена в `assemble_llm_content()`. Поведение не изменилось.
- **Дефолт модели сведён в один источник** — `config.py` (в `docker-compose.yml` убран дублирующий хардкод).

### Исправлено
- **Текстовый prompt-regression** был нерабочим с 0.6.0: `run.py` распаковывал 2 значения вместо 3 (`too many values to unpack`).

## [0.6.4] - 2026-07-13

### Добавлено
- **`register_validator`: проверка имени канала на запрещённые символы** — символы `$ # + / \ " '` (MQTT-разделители/wildcard и кавычки) ломают имя топика, и схема драйвера отклоняет такой шаблон при экспорте. Раньше это ловилось только на этапе скачивания (`schema_validator`), теперь — в реальном времени в редакторе.

### Изменено
- **Проверка по JSON-схеме драйвера при скачивании включена по умолчанию** — чекбокс в модалке скачивания теперь активен изначально и проверка запускается автоматически при открытии. Это дешёвая (локальная, без LLM) финальная проверка собранного шаблона: ловит ошибки сборки/структуры, которые не видны в пофайловой валидации регистров.

### Удалено
- **`register_validator`: убрана эвристика `probablySwitch`** («Enable/Disable/On-Off» в имени → возможно, должен быть switch). Это была единственная догадка по тексту имени, а не факт из схемы/драйвера, и она давала ложные срабатывания на легитимных value-каналах.

### Исправлено
- **Кнопка «Исправить через AI» больше не виснет на крупных шаблонах.** Раньше в LLM уходил весь шаблон с ожиданием полного исправленного набора в ответ — на устройствах с сотнями каналов (напр. WB-MR6C, 555) запрос длился минутами, вывод обрезался по лимиту токенов (`finish_reason=length`) → падал парсинг → кнопка «висла». Теперь в LLM уходят **только регистры с ошибками** (ERROR), а исправления вмёрдживаются обратно в полный шаблон строго по позициям (через временный тег `__fix_<i>`, т.к. `id` в шаблонах не уникальны — у condition-gated пар совпадают). Пустой набор ошибок → возврат шаблона без вызова LLM.
- **Подсказки fix-потока приведены к JSON-схеме драйвера.** Промпт «Исправить через AI» и `format_validation_errors` больше не хардкодят устаревший список `reg_type` (6 значений) — берут его из того же schema-derived перечня, что и валидатор. Иначе LLM могла «чинить» валидный `press_counter` обратно в неверное значение. Промпт также велит не трогать поля, которых нет в ошибках.
- **`register_validator`: убраны ложные ошибки/предупреждения, расходившиеся с драйвером wb-mqtt-serial** (сверено по исходникам драйвера). На реальном шаблоне WB-MR6C это давало 28 ложных ошибок + 35 ложных предупреждений — стало 0/0:
  - **reg_type/format/word_order/byte_order/channel_type теперь берутся из JSON-схемы драйвера** (той же, что у `schema_validator`), а не из хардкод-списка. Раньше `VALID_REG_TYPES` содержал 7 значений, тогда как драйвер знает ~45 (набор зависит от протокола устройства) — валидные типы `press_counter`, `relay`, `power`, `freq` и др. ложно помечались как ошибка; аналогично тип канала `w1-id` отсутствовал в хардкод-списке. Теперь списки не дрейфуют от драйвера.
  - **«Дубликат адреса» не срабатывает на condition-gated парах** (одна address, взаимоисключающие `condition`) — это штатный паттерн, драйвер оставляет один канал.
  - **Удалены правила без основания в драйвере**: «switch не использует enum» (драйвер публикует enum независимо от типа), «coil/discrete допускают только switch-подобные типы» (драйвер тип канала не ограничивает), «wo-switch должен быть write-only» (драйвер сам принудительно делает write-only), «многорегистровый формат требует word_order» (у драйвера дефолт big-endian).
  - **`string_data_size` не требуется**, если ширина строки задана через адрес `"N:offset:width"`.

## [0.6.3] - 2026-06-29

### Исправлено
- **Потеря флага readonly при round-trip**: при загрузке существующего JSON-шаблона атрибут `readonly` (без подчёркивания) у каналов и параметров не переносился в модель редактора — экспорт смотрит на `reg.readonly`/`reg.read_only`, а импортёр выставлял только `access`. В итоге при «скачал → загрузил обратно» отметки readonly пропадали. Добавлено `readonly` в roundtrip-поля импортёра.

## [0.6.2] - 2026-05-07

### Добавлено
- **Telegram-топики**: новая переменная `TELEGRAM_MESSAGE_THREAD_ID` — алерты можно отправлять в конкретный топик супергруппы (forum supergroup), а не только в общий чат. Если не задана — поведение прежнее (отправка в `TELEGRAM_CHAT_ID`).
- **Telegram-уведомления о сбоях LLM API**: классификация ошибок OpenAI SDK по 10 категориям (`quota_exceeded`, `auth`, `permission`, `not_found`, `bad_request`, `rate_limit`, `timeout`, `connection`, `server_error`, `unknown`) и серьёзности (CRITICAL/WARNING)
- **Антиспам**: CRITICAL — cooldown по категории (15 мин), WARNING — порог событий в окне времени (5 событий за 5 мин)
- **Билинговые алерты**: распознаются маркеры `insufficient_quota`, `billing_hard_limit_reached`, `billing_not_active`, `account_deactivated` (двойная проверка по `error.code` и тексту — для совместимых провайдеров) — алерт уходит немедленно
- **API**: блок `llm_errors_by_category` в `/api/metrics` — счётчики ошибок LLM API по категориям (только для серверного LLM)
- **Изоляция**: ошибки пользовательских (custom) LLM не репортятся — чужой ключ не наша зона ответственности
- **Настройки**: переменные `TELEGRAM_*` в `.env` (`TELEGRAM_NOTIFY_ENABLED`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_PROXY` и др. — см. `docs/config.md`)
- **Тесты**: 42 теста (20 — классификатор, 19 — notifier, 3 — интеграция в `analyze_document`)

## [0.6.0] - 2026-04-09

### Добавлено
- **Валидация регистров**: проверка format, reg_type, channel_type, address, enum по JSON-схеме драйвера wb-mqtt-serial (`wb-mqtt-serial-confed-common.schema.json`)
- **Авто-исправление**: синонимы LLM-ответов автоматически нормализуются (`uint16`→`u16`, `holding_register`→`holding`, `rw`→`readwrite` и т.д.)
- **LLM retry по валидации**: при >30% ошибок в ответе LLM — автоматический повторный запрос с описанием ошибок
- **UI**: красные/жёлтые бейджи ошибок валидации в строках таблицы регистров (тултип с описанием)
- **UI**: подсветка полей с ошибками в панели деталей (name, word_order, byte_order, string_data_size)
- **UI**: счётчик ошибок/предупреждений в тулбаре
- **UI**: кнопка «Исправить через AI» — отправка регистров с ошибками в LLM для автоматического исправления
- **UI**: модалка-предупреждение при скачивании шаблона с ошибками валидации («Скачать всё равно?»)
- **SSE**: новая стадия `validating` — отображается при проверке регистров после анализа
- **API**: эндпоинт `POST /api/validate` — валидация регистров, возвращает ошибки с i18n-ключами
- **API**: эндпоинт `POST /api/fix-registers` — SSE-исправление регистров через LLM
- **Форматы**: добавлены s24, u24, bcd8, bcd16, bcd24, bcd32, char8, string8 (из схемы драйвера)
- **Тесты**: 66 тестов бэкенд-валидатора, 11 тестов фронтенд-утилит валидации

### Изменено
- **Константы**: `FORMATS` расширен с 11 до 19 значений, добавлен `direct` в `REG_TYPES`
- **LLM pipeline**: `_parse_registers()` теперь применяет авто-исправление перед Pydantic-парсингом
